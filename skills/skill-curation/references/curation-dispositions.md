# Curation Dispositions

Choose a disposition based on behavior and authority, not aesthetics.

- **KEEP** — trigger and workflow remain distinct and healthy.
- **HARDEN** — same capability, but triggers/gates/evidence/recovery need strengthening.
- **MERGE** — two or more skills compete for the same owner role and their unique behaviors can coexist coherently in one class-level skill.
- **SPLIT** — one skill owns materially different authorities/triggers or has become an omnibus whose components should load independently.
- **DEPRECATE** — retained for compatibility/history but should no longer win normal routing; point to successor.
- **ARCHIVE** — preserve source/history outside runtime discovery.
- **CONVERT_TO_TOOL/PLUGIN** — primary value is deterministic executable behavior or always-on hooks rather than judgment guidance.
- **CREATE** — no existing owner can absorb a broadly reusable class-level capability without becoming incoherent.

## Merge test
Before merging, list every donor's unique triggers, invariants, failure modes, references, and outputs. The merged skill must preserve or deliberately supersede each one. A shorter library that silently loses capability is a regression.

## Split test
Split when independent parts:
- activate on different user situations;
- own different authority boundaries;
- require different tool access/risk posture;
- can evolve independently;
- cause excessive activation cost when bundled.

## Create test
A new skill should survive removal of today's project names, paths, incident IDs, and exact task narrative. If it becomes meaningless after that removal, it is probably a project note/reference rather than a reusable skill.
