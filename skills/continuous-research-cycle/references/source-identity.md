# Source Identity and Re-verification

A long-running corpus amplifies citation mistakes. Store source identity separately from the prose that cites it.

## On first verification
Record the canonical title/name, author/organization, publication/effective date, stable identifier (DOI/case/docket/version when present), canonical URL, source class, retrieval date, and the exact claim/evidence supported. Mark placeholders and inherited attributions explicitly as unverified.

## On reuse
Before a later cycle cites a persistent source, check the locked identity rather than copying a prior narrative citation. Re-fetch when the claim is time-sensitive, mutable, disputed, or load-bearing for a new conclusion. For static historical sources, a verified identity can be reused while new interpretive claims still require evidence.

## Contradictions
If the live primary source contradicts the corpus, preserve the old claim, mark it superseded/corrected, and update downstream status. Do not silently edit history or describe a non-reproduction as proof that an earlier event never occurred.

## Marginal evidence
Re-downloading an unchanged source is not automatically net-new research. It has marginal value when staleness itself is the question, when the fresh retrieval closes a prior uncertainty, or when its unchanged state is needed to test a time-sensitive hypothesis.
